# Meow Godot Launcher

A cross-platform (Windows, macOS, Linux) build manager for [Meowcat285/godot](https://github.com/Meowcat285/godot),
written in C# with [Avalonia UI](https://avaloniaui.net/).

It lists the fork's GitHub releases, installs editor builds and export templates side by side, launches them, and
keeps them up to date with **delta patches**, so updating a build downloads only what changed instead of the full
archive. Everything is served from GitHub Releases, no other hosting is needed.

![Main window](docs/screenshot.png)

## Features

- Browse releases of the fork, with their notes and commit.
- Install any number of builds side by side, launch them, open their folder, remove them.
- Delta updates from any installed build, chaining several releases when needed, with automatic fallback to the
  full download if anything doesn't check out.
- Optional export templates per build, copied into Godot's export templates folder when launching that build.
- Works offline with the releases it has already seen. Uses ETags so refreshing doesn't eat into GitHub's API
  rate limit, and accepts an optional token for heavy use.

## Download

Grab the archive for your platform from the [releases](https://github.com/Meowcat285/meow-godot-launcher/releases).
Each one is a single self-contained executable, no .NET installation needed.

| Platform | Asset |
| --- | --- |
| Windows (x64, also runs on Arm64) | `MeowGodotLauncher-win-x64.zip` |
| macOS (Apple Silicon) | `MeowGodotLauncher-osx-arm64.zip` |
| macOS (Intel) | `MeowGodotLauncher-osx-x64.zip` |
| Linux (x64) | `MeowGodotLauncher-linux-x64.tar.gz` |

The macOS app isn't notarized, so the first time, right-click it and choose **Open**, or run
`xattr -d com.apple.quarantine "Meow Godot Launcher.app"`.

Builds are stored in `%LOCALAPPDATA%\MeowGodotLauncher` on Windows, `~/Library/Application Support/MeowGodotLauncher`
on macOS, and `~/.local/share/meow-godot-launcher` on Linux. The library folder can be changed in Settings.

## How delta updates work

Delta patches are generated by the fork's CI and published as extra assets of each release:

1. When the fork's `🔗 GHA` workflow publishes a release, the
   [`🩹 Delta patches`](https://github.com/Meowcat285/godot/blob/slop/.github/workflows/delta_patches.yml) workflow
   runs [`misc/scripts/generate_delta_patches.py`](https://github.com/Meowcat285/godot/blob/slop/misc/scripts/generate_delta_patches.py).
   It extracts each package (editor archives and export templates) of the new release and of the previous two
   releases, and for every package and older release writes a `<package>.from-<tag>.mgdelta` file.
2. A delta holds one operation per file of the new package: **copy** an unchanged (or renamed) file from the
   installed build, **patch** a changed file, or **add** a new one. Patches use bsdiff, which copes well with
   recompiled executables where most code just moved, compressed with zstd. Every operation carries the expected
   SHA-256 of its output. Zip archives inside a package (like `macos.zip` and `ios.zip` in the export templates)
   are compressed, so patching them whole doesn't work: they get one operation per entry instead, and the launcher
   rebuilds the archive. A rebuilt archive has the same entries as the original but not the same bytes, so its
   entries are what gets verified.
3. `meow-launcher-manifest.json` lists every package's files and its available deltas with their sizes and checksums.

When installing a release, the launcher looks at the builds already installed and the manifests of the releases in
between, and picks the cheapest way to get there: a single delta, a chain of deltas through intermediate releases,
or the full archive when that's smaller or no delta path exists (for example for releases published before the
patch workflow existed). Patching happens in a staging folder; the result is verified file by file and only then
moved into place, so a failed or cancelled update never breaks an installed build. Installed builds are kept
byte-identical to the release archives so they can serve as the base of later updates.

For a sense of the savings, here's what updating from `2026.10.5` to `2026.10.6` downloads:

| Package | Full download | Delta |
| --- | --- | --- |
| Linux editor | 100 MB | 7.5 MB |
| Windows editor | 105 MB | 7.6 MB |
| macOS editor | 153 MB | 9.0 MB |
| Export templates | 474 MB | 108 MB |

The 161 MB Linux editor binary alone patches with 2.8 MB. Most of what's left in the templates delta is the
Android APKs and AARs, which are compressed archives the launcher doesn't rebuild.

### Why no S3 or other storage

GitHub Releases is enough: deltas are small, a release can hold up to 1000 assets of up to 2 GiB each, and asset
downloads from github.com aren't subject to the API rate limit. A separate storage provider would only be worth it
for things Releases can't do, like serving byte ranges of a single shared archive or keeping patches for many more
releases than are sensible to attach. Nothing in the current design needs that.

## Building

Requires the [.NET 10 SDK](https://dotnet.microsoft.com/download).

```sh
dotnet build MeowGodotLauncher.slnx
dotnet test MeowGodotLauncher.slnx
dotnet run --project src/MeowGodotLauncher
```

To produce a self-contained single-file executable like the released ones:

```sh
dotnet publish src/MeowGodotLauncher -c Release -r linux-x64 -o publish   # or win-x64, osx-arm64, osx-x64
```

Pushing a `v*` tag builds all platforms in CI and publishes them as a GitHub release.

### Layout

- `src/MeowGodotLauncher.Core`: everything that isn't UI. GitHub client, library of installed builds, installer,
  update planner and delta patch applier.
- `src/MeowGodotLauncher`: the Avalonia app (MVVM, with CommunityToolkit.Mvvm).
- `tests/MeowGodotLauncher.Core.Tests`: unit tests. `Fixtures/` holds a small delta made by the real generator,
  so the C# applier is tested against the Python generator's output; `Fixtures/make_fixtures.py` regenerates it.

The delta formats are defined on both sides, in `generate_delta_patches.py` in the fork and in
`src/MeowGodotLauncher.Core/Delta` here. Keep them in sync, and bump the `format` number on incompatible changes.
